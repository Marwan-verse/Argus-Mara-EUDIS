# Team communication and accounts

**Where:** sign-in screen and **SOC session** in the header. Browser account
administration is at `/admin/` on the configured SOC server.

| Feature | What it does |
|---|---|
| Sign-in choices | Shared SOC sign-in, offline/demo access, or a local Docker two-window demonstration. |
| Create account | Request an account; an administrator must grant group access before sign-in. |
| Remember sign-in | Optionally retain a server token in the OS keychain for up to eight hours. |
| Team/private sessions | Create or join a session using an eight-character, ten-minute invitation; supports up to 16 people. |
| Peer verification | The host locks the roster; participants compare and check each peer's safety code before sending. |
| Encrypted sharing | Chat, share selected contacts, send temporary map pings and share vessel reports when everyone has the required tool rights. |
| Leave/sign out | Leaving ends the room; sign-out revokes and removes the saved sign-in. |
| Native administration | Administrators manage users, group membership, passwords, permissions and session revocation. |
| Browser administration | Search/filter accounts, approve, ban/reinstate, reset passwords, revoke sign-ins, manage groups and inspect recent audit records. |

Available tools depend on current group permissions. Administrator status is
separate. Account/group changes can revoke sign-ins or close rooms. Secure chat
verification starts again after a restart. Team messages are analyst
communication, not operational tasking.
